# akdi-makine

## Windows Auto-Updates

Packaged Windows x64 NSIS builds check for updates at `https://akdimakine.com/test-machine/`. The app downloads updates in the background and asks before restarting to install one. Development runs and macOS/Linux builds do not use this feed.

### Hosting Setup

Configure the web host so this public HTTPS directory maps to the URL above:

```text
/test-machine/
	latest.yml
	AKDIMAKINE-Windows-<version>-Setup.exe
	AKDIMAKINE-Windows-<version>-Setup.exe.blockmap
```

The exact installer and blockmap names are generated by Electron Builder and referenced by `latest.yml`; upload those generated names unchanged. Each release replaces `latest.yml` and adds that release's installer and blockmap. Keep prior versioned installer files available if you need rollback or older clients may still request them.

Required host behavior:

- Serve every file over valid HTTPS without an interactive login. Installed clients cannot use a secret embedded in the application as feed authentication.
- Return `200 OK` for `latest.yml` and installer downloads, and support HTTP byte-range requests (`Accept-Ranges: bytes`) for large files.
- Do not cache `latest.yml` for a long period. Use `Cache-Control: no-cache, no-store, must-revalidate` (or equivalent) so clients see each published version promptly.
- Installer and `.blockmap` files may be cached as immutable/versioned artifacts. Serve YAML as `text/plain` or `application/octet-stream`, and installer/blockmap files as `application/octet-stream`.
- Preserve the `/test-machine/` path and trailing slash, or update `publish.url` in `electron-builder.json5` and publish matching artifacts at the new URL.

### Release Checklist

1. Increment `version` in `package.json` using a higher semantic version than the current release.
2. Build the Windows x64 NSIS installer on Windows. The artifacts are written under `release/<version>/`.
3. Confirm the output includes the setup `.exe`, matching `.exe.blockmap`, and `latest.yml`. Verify `latest.yml` points to the exact uploaded installer filename and expected version.
4. Sign the installer with the production Windows Authenticode certificate. Keep the certificate and password in protected release environment secrets; never commit them.
5. Upload the generated installer, blockmap, and `latest.yml` to the website's `/test-machine/` directory. Make the new `latest.yml` live only after both versioned files are present.
6. Verify `https://akdimakine.com/test-machine/latest.yml` and the referenced artifacts are reachable from a representative client network.
7. Install an older released version, publish a newer test version, and verify the app detects/downloads it, prompts for restart, and launches at the new version after confirmation.

Do not change the configured `appId` (`com.akdimakine.AKDI-MAKINE`) between releases. If any older installers were distributed with a different effective app ID, test an upgrade from those installs before treating this feed as production-ready; they may require a one-time reinstall.
